## 4. What the label is learnable to, and how much is linear

- Ceiling under ind24 x 16: MCC 0.21-0.23 (A), 0.10-0.12 (B), 0.16-0.20 (C); AUROC macro 0.68 / 0.60 / 0.65; balanced accuracy 0.45 / 0.41 / 0.45 against 0.333 chance. RIDGE holds 94% (A), 100% (B), 94% (C) of the best MCC and 96-99% of the best AUROC. The argmax signal is linear in the 24 indicators to within 0.013 MCC. The only consistent non-linear gain is in ranking, not classification: neural AUROC exceeds RIDGE by +0.024 (A) / +0.005 (B) / +0.015 (C) and logloss is 0.02-0.04 lower, at seed std <= 0.005, so it is real but does not move argmax MCC.
- Most of the learnable content is the gbb trigger axis again: the learning-free rule (guard_metric < 0.3 AND bb_width > 0.035) scored against THIS label (`trig_rule_mcc`) gives 0.171 / 0.099 / 0.130, i.e. 80% / 85% / 70% of the best model. Inside the trigger, every model orders BUY/SELL at AUROC 0.55-0.61 (`trig_*_auroc`), the same 0.56-0.63 band as on gbb. The 24 indicators are, for this label too, mainly a volatility-state signal.
- Per class: SELL is the better-classified side on precision/F1 (prec 0.44-0.52 vs base 0.29-0.42; F1 0.31-0.43) but that is mostly prevalence; BUY precision 0.23-0.27 against base 0.16-0.22 and F1 0.27-0.36. AUROC is near-symmetric (SELL 0.63 / 0.58 / 0.63, BUY 0.63-0.67 / 0.57 / 0.62): neither side carries more rankable information. HOLD is the easiest class (AUROC 0.70-0.72 on A; F1 0.72).
- Hardest window: B on every metric (MCC 0.10-0.12, AUROC 0.59, trigger-rule 0.099). Hypothesis: B's test window is a higher-vol regime (HOLD share 35% vs 45% in train, SELL 42%); with fixed 2% barriers the label there is almost purely "which barrier first", a direction call that the vol-state indicators do not carry, and the train/test prior shift costs the argmax on top. An ATR-scaled barrier is the direct test of that (s.6).

## 5. Against the gbb result (architecture question, inputs)

On gbb every from-scratch type reached the label's own two-threshold rule (0.66 / 0.64 / 0.64) and RIDGE sat 0.10-0.11 below it, so "neural beats linear by 0.10" was the non-linearity of the label's AND, not of the market. On a label with no indicator in it the neural-over-RIDGE gap is +0.013 at best and negative on one window; the between-type spread (0.01-0.03) is the same size as that gap. Both facts say the same thing: with ind24 x 16 bars as input, architecture is not a lever on either label, and the gbb 0.64 was the rule, not the models. The place to look is the input, not the type (Constitution III and the study's own "information ceiling moves only with new information"): a 0.17-MCC label may well be the honest target, and if so the architecture study cannot improve on it and should stop treating type choice as the open question. What the study can still measure cheaply is which label definition and which input representation move the ridge line.

## 6. Follow-ups named in the spec (SC-003), as options; cost quoted for the full six-type grid (~1 h wall measured, 2 h budgeted) and for the screen in the last bullet

- **A. ATR-scaled barriers (H 48, +/- k x ATR, k in {1, 2, 3}).** Highest information per hour: it removes the vol-regime dependence of a fixed 2% barrier that s.4 identifies as B's failure mode and that makes the class prior drift 9 pp between train and test. Expected: HOLD share stable across windows, B rises toward A/C, RIDGE moves too. Cost: label code (Framework/TrainingSignals.py already has ATR access) + 3 variants x screen. Run first.
- **B. Horizon x width grid** (H in {12, 24, 96} x width in {1%, 3%, 5%}, jointly per the project's H-x-threshold finding, not one axis at a time). Information: where MCC and prevalence peak; longer H raises PERSISTENCE and MCC by construction (gbb H 8 -> 0.76) and is exactly the case the Constitution warns about, so read it as a map, not a target. Cost: 9 variants x screen (~1.5 h), 18 h as full grids: run only as the screen.
- **C. Raw OHLCV inputs (log returns, range, log volume over the same 16 bars) vs ind24, on this label.** The direct test of whether the indicator transform discards information the label needs. Expected null (indicators are functions of OHLCV; the memory's 85-indicator battery added zero to triple barrier), but a null here closes the input-representation question for price-only inputs and a positive would be the first one in the study. Cost: one input_set in `features.py` + one grid or screen. Run second.
- **D. seq_len 48-96 (context = horizon).** Lowest priority: on gbb window/context changed nothing, on this label the sequence types (LSTM, TCN, TRANSFORMER) are at or below the flat MLP, so more context is unlikely to help; cost scales with seq_len (LSTM 6 -> ~20 min/seed).
- **Shrink the grid for label-variant screening: yes.** RIDGE (3 seeds) + MLP_FAM w64 (2 seeds): MLP is tied-best on every window, 1.1 min per seed over three windows, no sequence machinery; together ~5 min compute per variant vs ~1 h. Promote a variant to the six-type grid only if MLP - RIDGE >= 0.02 MCC on 2 of 3 windows or RIDGE itself moves by >= 0.05 pooled. Keep PERSISTENCE/MAJORITY in every screen (they cost nothing and re-verify the label on the row, the lesson of the 08:35 defect).
