# T005 — the NNMT control baseline

The pre-inheritance control (`NNMT_MLX_Base`), established before anything is
varied. Every later delta in this feature is measured against these numbers.

## What the control is, and why it had to be rebuilt

"NNMT today" is a mixture and is not a valid control for anything (research R1):
its models on disk were trained with a label gain threshold of 0.007 while the
class now reads 0.020, and its take-profit moved 0.032 → 0.022. Both changes
arrived by INHERITANCE from work done for NNNC and neither was tested on this
family. The control undoes exactly those two, and nothing else.

| setting | control | NNMT today | source |
|---|---|---|---|
| label gain/loss threshold | **0.007** | 0.020 | `NNMT_MLX_Base.py` class attribute |
| `cexit_take_profit` | **0.032** | 0.022 | `NNMT_MLX_Base.json` |
| everything else | unchanged | unchanged | generated from NNMT's measured live config |

`NNMT_MLX_Base.json` was not hand-written: it was GENERATED by loading
`NNMT_MLX`, running `ft_load_hyper_params` exactly as `ft_bot_start` does, and
dumping the merged parameter values — then changing the single take-profit key
under an assertion that it was 0.022 beforehand. That removes the possibility of
a transcription error in the control, and satisfies FR-022 by pinning every
value rather than letting any of them track shared defaults.

## The model on disk matches the control's label (T003) — no retrain

- `saved_data/NNMT_MLX/NNMT_MLX.safetensors` was written **2026-09-03 23:29**.
- `MIN_BUY_GAIN_THRESHOLD` was 0.007 from 2026-05-31 (`129620b`) until
  **2026-09-06 11:07** (`543d198`), which raised it to 0.02.

The model predates the change, so it was trained at 0.007 and agrees with the
control. **Phase 1 therefore required no training at all.**

## A live-parameter finding (Constitution IV)

`entry_rvol_threshold` is declared `DecimalParameter(..., decimals=1)`, so
NNMT's swept value of **0.25 is rounded to 0.2** before it reaches the guard.
The value written in `NNMT_MLX.buy_params` is not the value the strategy runs.

The control pins **0.2** — what NNMT actually executes — so the control is a
faithful reproduction of today's behaviour rather than of today's source code.
Nothing here changes as a result; it is recorded because the spec's
configuration table says 0.25 and should be corrected, and because a swept
optimum that cannot be expressed at the resolution of its own parameter is worth
knowing before anyone sweeps it again.
