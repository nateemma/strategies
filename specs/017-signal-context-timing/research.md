# Phase 0 Research: signal-context-timing

**Date**: 2026-09-16 · Measurements taken during planning are dated and reproducible.

---

## R1 — The signal set is reconstructable offline, and it is faithful

**Decision.** Recover every entry signal — admitted and masked — with
`research/labelfree/es/panel.py::entries()`, which reimplements
`BaseStrategy.populate_entry_trend` (886-957) over probability side-cars generated by the
**production backtest path**.

**Why this is not the second-inference-path hazard.** `es/signals.py` explicitly rejected
offline *inference*, because this repository has a recorded case of predict-time scaling
diverging from production (the single-task GAN scaler bug, worth 1.53 pp and found only by
hunting). That prohibition is about **running the model** a second way. This feature runs the
model **zero** times: it consumes side-cars the production path already produced and recomputes
only the **gate**, which is arithmetic over recorded columns.

**Validated, not assumed** (f08, 2026-09-16): **70 of 71** recorded trades have their entry bar
in the reconstructed signal set. The single miss is SOL/USDT `2024-12-21 16:15` — the **first
bar of the test range**, where rolling indicators lack history. Documented, not hidden.

**Consequence.** US1, US3 and the masked-signal census cost **zero backtests**.

## R2 — "Signal" means an EVENT, not a bar

**Decision.** A signal is a **contiguous run** of bars where `enter_long` is set. Runs are
collapsed to their first bar.

**Rationale, measured.** f08's test range holds **139 signal bars** but only **120 distinct
events** — 14% of bars are continuations of a signal already counted. Counting bars would
inflate every masked-signal statistic by that factor and would double-count a single trading
opportunity that happened to persist for three candles.

**Restated masked-signal rate.** 120 events, 71 admitted → **49 masked, 41%**. This supersedes
the earlier "~43%" figure, which was inferred from `--eps` trade counts rather than measured.

## R3 — The confound test: is the repeat signal anything more than "underwater"?

**Decision.** Two tests, both pre-registered, on the same data:

1. **Primary — stratified.** Bin open positions by **unrealised P&L at the moment of the repeat
   signal** (deciles of the pooled distribution). Within each stratum compare final outcomes of
   positions that did versus did not receive a repeat signal, combining strata with a
   **Cochran-Mantel-Haenszel** test. Non-parametric, no functional form assumed.
2. **Secondary — regression.** Logistic regression of final win on
   `unrealised_pnl + received_repeat_signal`, reporting the coefficient, its interval and the
   marginal effect.

**TWO EFFECT SIZES, AND THEY ARE NOT INTERCHANGEABLE.** The tests above measure a **win-rate**
difference; the study's resolution limit of 7.633 pp is an **annualised-return** quantity. The
motivating effect is 14.8 win-rate points, which would clear 7.633 numerically while carrying no
information about return at all. Applying the floor to the wrong currency turns Principle III's
gate from a defence into a rubber stamp.

So `confound.py` reports both and gates on only one:

    effect_winrate_pp    = win_rate(repeat) - win_rate(control)          # reported
    effect_return_pp_yr  = d_mean_profit_ratio * 9.0 * trades_per_year   # GATED on 7.633

The 9.0 is pp per unit `profit_ratio` under the fixed-stake convention (900 on a 10,000
wallet) — the same constant brief 013 established after compounding once read a real
+23.46 pp/yr as -19.06.

**Rationale.** If the model re-fires mainly after price has fallen, "received a repeat signal"
is a proxy for unrealised loss, and losing trades ending badly is close to tautological. The raw
finding (win 0.783 vs 0.635, Fisher p = 0.0049) cannot distinguish the two.

**FR-002's matching rule matters more than the test choice.** Controls MUST be positions **alive
at the same holding age**. A control drawn from all trades compares different holding durations,
and since trades that survive longer are systematically different, that alone would manufacture
an effect.

**Alternative rejected.** Comparing only final outcomes with no conditioning — that is the
measurement already in hand, and it is exactly what this stage exists to challenge.

## R4 — Unrealised P&L must be reconstructed, because the archive does not carry it

**Decision.** Rebuild each trade's per-bar unrealised P&L from its entry price and the pair's
OHLCV over its holding window, using `close` for the running mark.

**Rationale.** Backtest archives record open/close rates and dates, never the path between. The
whole confound test is about a mid-trade quantity, so the path is mandatory.

**Convention, and it is the one that bit brief 013.** Marks are computed as a ratio against
entry and converted to percentage points **additively**; nothing is compounded across concurrent
positions. Compounding pooled trades once read a real +23.46 pp/yr as −19.06.

**Known limit, recorded.** `close`-based marks understate intrabar excursion. For a signal-timing
question this is acceptable — the signal itself is evaluated on closed bars — but any claim
about stop proximity must use `low`, not `close`, and must say which it used.

## R5 — Multiple testing is declared before looking

**Decision.** Four first-signal context hypotheses, fixed now, **with their windows fixed too**
— an undefined window is a silent free parameter inside a test that claims exactly four
hypotheses:

| hypothesis | definition, frozen |
|---|---|
| `bars_since_prev_signal` | bars since the previous signal event on the same pair |
| `prev_signal_won` | outcome of the previous **closed** admitted trade on the pair; null if still open |
| `drawdown_from_high` | close vs the **96-bar (1-day)** trailing high, matching this repository's window convention |
| `burst_position` | index within a burst; signals more than **24 bars (6h)** apart are separate bursts, chosen to exceed the 3-10h median hold so a burst cannot span a completed trade |

Threshold **α = 0.05/4 = 0.0125** (Bonferroni), stated before any test runs.

**Rationale.** Testing four features at α = 0.05 yields a false positive roughly one time in
five. Bonferroni is conservative and, with only four pre-declared hypotheses, cheap. Declaring
the count afterwards is the failure this guards against.

**Consequence of FR-023.** If the confound gate kills the repeat-signal arm, this sweep loses
its motivating prior and becomes **EXPLORATORY** — at which point this correction stops being
hygiene and becomes the only thing standing between a sweep and a false finding.

## R6 — `--eps` is fenced to a single job

**Decision.** Position stacking is used **only** to give masked signals an observable outcome.
Every figure it produces is labelled *not reproducible in dry/live*. No delta against the
control is computed from it.

**Rationale.** freqtrade's own help says results under `--eps` "cannot be reproduced in dry/live
trading". Measured on f08: `--eps` showed +1.27 pp where the deployable analogue delivered
−6.31 pp — the two differ structurally (independent stops versus a shared averaged stop), and
that one difference reversed the sign. An `--eps` P&L figure is not a weak edge estimate; it is
an estimate of a different system.

**What it legitimately measures.** Whether masked signals, taken as independent trades, resemble
admitted ones in win rate and excursion. That is a statement about **signal quality**, which is
the question — not about returns.

## R7 — The exit-side rule, and the stack it must be distinguished from

**Decision.** A repeat signal on an open position triggers an exit-side action only: tighten the
stop, or exit. Entries stay byte-identical. Implemented as a mixin in `NNNC/_signal_context.py`,
following `_hold_window.py` and `_position_adjust.py`.

**Rationale.** A repeat signal arrives while freqtrade has already discarded it as an entry, so
the only place it can act is on the position already open. It arrives **before** that trade's
outcome is known, which is what makes it a predictor rather than a description.

**The action is pre-registered, not searched.** Tighten the current stop distance by **0.5**.
"Tighten the stop" without a magnitude is a free parameter, and searching it alongside the
trigger is the joint search Principle VIII forbids — the failure that took brief 05 to PBO
0.7128 over 48,015 evaluations. An outright exit is a labelled sensitivity that cannot produce
the verdict.

**"Distinct" is a number, not a judgement.** Overlap is the share of the rule's triggers on
trades where the existing stack fired anyway **within 8 bars**; **≥ 0.70 is inert**. Feature 016
shipped a kill gate keyed on undefined "redundancy" and the analyze pass had to put a number on
it before implementation; the same mistake is not repeated here.

**The redundancy that most likely kills it.** `BaseStrategy` already runs `stoploss_grace` and an
ATR-adaptive stop, both reacting to adverse moves. The motivating effect — 36.5% vs 21.7%
trailing-stop exits — was itself measured **through** that stack, so the trigger may simply fire
where the stop was about to fire anyway. FR-022 requires the overlap measured before any
performance figure; SC-019 makes large overlap inertness rather than a result.

**Recorded caution.** `feedback_exit_params_inert_under_custom_stoploss`: `trailing_*` and
`self.stoploss` do nothing while a custom stoploss path owns the stop. Any exit-side change must
prove it acts through the path that is actually live.

## R8 — Arms reuse fold weights; nothing is retrained

**Decision.** Each arm class overrides `get_model_path()` to the ungated fold's directory, and an
assertion refuses to run unless those weights exist and no new `saved_data/` directory appears.
Reuses the pattern in `research/posadj/arms.py`.

**Rationale.** `BaseNNStrategy.get_model_path` keys off `self.__class__.__name__`, so a new class
name means a new weights directory — and `evaluation/run_folds.py` records the consequence in its
own docstring: a class with no model of its own **trains inside its own backtest**, fitting the
evaluation window, silently, with returncode 0. This feature changes no model input, so
retraining would introduce a difference the comparison is not trying to measure.

---

## R9 — Liveness probes get their own sanity check

**Decision.** Every liveness count (signals blocked, stops tightened, trades affected) is paired
with a **null-case assertion**: an arm reported as affecting nothing must be **byte-identical**
to its control.

**Rationale.** Recorded three times on 2026-09-15, each reporting zero on a working arm: a field
absent from exported trade dicts read through a `.get(key, 1)` default; a count derived as
`round(stake/base)-1` when wallet caps make the multiples fractional; and a markdown parser that
returned 3 rows of 32 because a column contained the delimiter. A broken probe and a true null
produce the same output, and the null-case check separates them for one line of code.

## Open risks carried into Phase 1

1. **The effect is a proxy for being underwater.** Most likely single outcome. Pre-registered as
   a KILL of the repeat-signal arm, after which US3 continues as EXPLORATORY.
2. **The exit trigger is the existing stop in disguise.** Second most likely; pre-registered as
   inertness under Principle IV, not as a null about signal context.
3. **A context feature is significant but tiny.** Pre-registered: anything inside 7.633 pp is
   "not resolved" whatever its p-value.
4. **`/tmp` is cleared and the side-cars vanish.** Mitigated by copying **only** `es_sink`
   (366 MB) to durable, **gitignored** storage as the first task. The panel cache at
   `/tmp/lf/es_panels` is **2.1 GB and must NOT be copied**: measured 2026-09-16, it rebuilds
   from side-cars in **3.4 s per fold (~1.7 min for all 30)**, so preserving it would add 2.1 GB
   to a git repository to save under two minutes.
