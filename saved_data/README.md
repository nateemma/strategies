# saved_data/

This directory holds **trained model weights, scalers, and related artifacts**
produced by running the strategies in this repository (e.g. NNNC/NNMT
classifiers, the GAN generators/discriminators, and TS_Gain models).

## Why these files are not tracked in git

Model weight files are **generated artifacts**, not source code:

- They are large (individual `.keras` / `.safetensors` / `.sav` files in this
  project can exceed 40 MB; the aggregate directory has historically been
  100+ MB). GitHub warns on files over 50 MB and rejects pushes containing
  files over 100 MB.
- They are reproducible. Given the strategy code and training data, the
  weights can be regenerated by retraining.
- They change frequently (every training run), which would bloat git history
  with binary diffs that are effectively unreadable.
- Committing them makes clones slow and repository size unbounded.

For these reasons, everything under `saved_data/` is excluded via
`.gitignore`, with this `README.md` explicitly allow-listed so the directory
and its rationale remain discoverable.

## How to populate this directory

Retrain the relevant model(s) using the corresponding strategy or GAN
creation script. For example:

- NNNC/NNMT classifiers: run the associated strategy in training mode (see
  `Framework/BaseNNStrategy.py` and the specific strategy subclass).
- GANs: run the `GANs/Create*.py` scripts (e.g. `CreateWGAN.py`,
  `CreateCtabGanPlus.py`, `CreateMTWGAN.py`).

Each script writes its outputs into a subdirectory of `saved_data/` named
after the model.

## Sharing trained weights with teammates

If you need to share trained weights outside of git, consider:

- Copying the relevant subdirectory directly (e.g. via shared storage or a
  cloud bucket).
- Using [Git LFS](https://git-lfs.com/) for a subset of weights you want
  version-controlled — note this requires re-configuring `.gitignore` and
  adding LFS tracking rules.
- Exporting to a model registry (MLflow, Weights & Biases, etc.) if the
  project grows to need one.
